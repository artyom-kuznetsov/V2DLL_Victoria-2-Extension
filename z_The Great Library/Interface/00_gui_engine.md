# 00. GUI Engine: обратный каркас интерфейса

Целевой бинарник: Victoria 2 3.04, 32-bit x86. Все RVA далее = VA из Ghidra минус 0x400000; в рантайме адрес считается от базы v2game.exe.

## Базовые пути обхода дерева

Декларация элемента в .gui превращается движком в рантайм-виджет. У экрана-вьюхи (CTechnologyView, CBudgetView и т.д.) известный контейнер UI лежит по смещению +0x4C. От него дерево ищется по именам:

| Операция | Вызов | Смещение слота | Аргумент |
|---|---|---:|---|
| Найти вложенное окно | контейнер/окно | 0x6C | указатель на GStr с именем |
| Найти кнопку/дочерний виджет | окно | 0x34 | указатель на GStr с именем |
| Найти scrollbar/slilder | окно | 0x4C | указатель на GStr с именем |
| Получить имя элемента | виджет | 0x44 | нет, возвращает GStr* |

Соглашение этих вызовов: thiscall. В коде мода используется __fastcall с фиктивным EDX.

## Строка движка GStr

Мини-аналог MSVC std::string:

    struct GStr {
        char data[16];
        uint32_t size;   // +0x10
        uint32_t res;    // +0x14
    };

Если res <= 15, строка лежит прямо в data. Если res > 15, data трактуется как указатель на внешний буфер. Удобные операции: чтение через GStrText, запись без перевыделения через GStrSet, создание через MakeStr.

## Подписка кнопок

У кнопки встроенный Observable лежит по смещению +0x54. Добавление слушателя - виртуальный вызов Observable+0x04 с одним аргументом.

Формат CButtonObserverGlue, подтверждённый живыми объектами:

| Смещение | Содержимое |
|---:|---|
| +0x00 | vftable |
| +0x04 | владелец/контекст |
| +0x08 | обработчик клика |
| до 0x2C | остальные слоты слушателя, обычно нули в собственном клоне |

Размер обычной кнопочной склейки - 44 байта. Опорная vftable - RVA 0xA0A58C; trampoline клика - RVA 0x5CD610. Обработчик вызывается примерно как: owner = glue+4; method = glue+8; method(owner).

Правило: на каждую кнопку нужен свой клон склейки. Нельзя использовать один обработчик для нескольких кнопок, потому что в +0x08 хранится ровно один метод. Безопасный шаблон:

    void* button = VCall1(host, VT_FIND_CHILD, makeName(name));
    memcpy(glue, view + viewOffGlue, 44);
    *(void**)(glue + 0x08) = customThunk;
    void* observable = (unsigned char*)button + 0x54;
    VCall1(observable, 0x04, glue);

Для topbar-кнопок исходную склейку лучше не копировать целиком: копируются только vftable и +0x04, а остальные поля обнуляются, иначе наведение и правый клик могут вызывать чужие обработчики.

## Известные экраны и точки подписки

Подписка делается не через отдельный API, а через перехват регулярно вызываемого слота вьюхи. Это устойчиво к пересозданию экрана: адрес вьюхи сравнивается, при смене подписка повторяется.

| Класс | vftable RVA | Слот | Тип слота | offGlue | Контейнер | Вложенное окно |
|---|---:|---:|---|---:|---:|---|
| CTechnologyView | 0xA17FA4 | 11 | Update | 0x60 | +0x4C | selected_tech_window |
| CBudgetView | 0xA059F0 | 10 | Tooltip | 0x5C | +0x4C | нет |
| CProductionView | 0xA0FECC | 10 | Tooltip | 0x120 | +0x4C | нет |
| CPoliticsView | 0xA0E458 | 10 | Tooltip | 0x00 | +0x4C | нет |

Сигнатуры:

    typedef void (__fastcall *ViewUpdate)(void* view, void* edx);
    typedef void* (__fastcall *ViewTooltip)(void* view, void* edx, void* retBuf, void* element);

Порядок хука:

1. Дождаться вызова слота.
2. Вызвать оригинал.
3. Если указатель вьюхи новый, найти контейнер и нужные кнопки.
4. Подписать свои клоны CButtonObserverGlue.
5. Для tooltip-слота можно изменить возвращаемый буфер GStr после оригинала.

## Ползунки

Ползунок ищется не слотом кнопок 0x34, а слотом 0x4C. Подобъект Observable также лежит на +0x54.

Известные слоты scrollbar:

| Операция | Смещение |
|---|---:|
| GetValue | 0x10 |
| SetValue | 0x1C |

SetValue принимает целое значение и два служебных аргумента. В существующем коде вызов выглядит как SetValue(value*1000, 1, 1) для ползунка громкости.

Для слушателя изменения значения используется CScrollbarObserverGlue. Известная vftable настроек - RVA 0xA14404. Слот обработчика тоже +0x08; владелец при собственном клоне часто ставится равным самому ползунку.

## Restart/True Exit

Элемент true_exit объявлен в interface/menubar.gui внутри menu_panel.

Активация: ENABLE_RESTART_GAME_BUTTON=1.

Механика:

1. Хук подписки menu_close_button проверяет оригинальный обработчик RVA 0x26F060 и место вызова RVA 0x266814.
2. Из menuOwner+0x1D24 берётся контейнер menubar.
3. Слотом 0x6C ищется menu_panel, затем слотом 0x34 ищется true_exit.
4. Кнопка получает отдельный glue размера 0x50.
5. Клик запускает процесс заново с той же командной строкой и вызывает ExitProcess.

Есть дебаунс 500 мс. Если подписка оригинального menu_close_button не совпала по сигнатуре, true_exit остаётся неактивным.

## Методика добавления нового UI

Минимальный чеклист:

1. Найти элемент в .gui и записать полный путь родителя.
2. Найти vftable класса экрана и регулярный слот Update или Tooltip.
3. Определить смещение живой CButtonObserverGlue внутри вьюхи.
4. Найти родителя: контейнер +0x4C, затем слот 0x6C для окна, затем слот 0x34 для кнопки.
5. Сделать индивидуальный клон glue, подставить собственный naked-thunk в +0x08.
6. Добавить вызов Observable+0x04.
7. Проверить пересоздание экрана и reload интерфейса: старый указатель кнопки и glue уничтожаются.
8. Логировать только установку и ошибку; не оставлять покадровый спам.
