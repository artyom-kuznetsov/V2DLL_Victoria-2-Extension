# 03. Topbar и музыкальный плеер

Источник разметки: interface/topbar.gui. Кнопки и ползунок добавлены модом.

## Элементы

| Имя | Тип | Расположение | Действие |
|---|---|---|---|
| button_fe_player_pause | guiButtonType | topbar | пауза/продолжение текущего DirectShow-графа |
| button_fe_player_next | guiButtonType | topbar | пропуск текущего трека |
| fe_player_volume_slider | scrollbarType | topbar | громкость музыки, диапазон 0..100 |
| button_speedup | guiButtonType | topbar | ускорение времени |
| button_speeddown | guiButtonType | topbar | замедление времени |

Оба музыкальных переключателя и ползунок активны при ENABLE_MUSIC_PLAYER=1. MUSIC_FAIR_RANDOM не создаёт UI, но влияет на выбор следующего трека.

## Подписка topbar

Движок не знает имена button_fe_player_*. DLL подписывает их сама.

Окно topbar хранится в topbar+0x20. Живая кнопочная склейка берётся из topbar+0x218. Перед использованием проверяется её vftable и click trampoline: метод должен совпасть с 13-байтовой сигнатурой CButtonObserverGlue.

Порядок:

1. Хукируется построение topbar FUN_007129A0, RVA 0x3129A0.
2. Есть два места вызова: конструктор topbar RVA 0x30D090 и vftable slot 0 для reload интерфейса RVA 0xA113D0.
3. Сначала вызывается оригинал.
4. Из нового topbar берётся окно и исходная склейка.
5. Слотом окна 0x34 ищутся обе кнопки.
6. Для каждой создаётся чистый glue: vftable исходной склейки, +0x04 владелец, +0x08 собственный thunk, остальные поля нулевые.
7. Кнопка подписывается через Observable+0x04.

Пересоздание интерфейса безопасно: hook вызывается заново. Дебаунс 250 мс предотвращает пропуск двух треков при двойной подписке.

## Глобальное состояние музыки

| Значение | RVA / смещение | Смысл |
|---|---:|---|
| музыкальный объект | 0xF1CB34 | CMusic на DirectShow или CNullMusic |
| состояние плеера | 0xB20C3C | 0 stop, 1 play, 2 pause, 3 no sound |
| IMediaControl | 0xB20C4C | интерфейс DirectShow |

Виртуальные слоты музыкального объекта:

| Слот | Смещение | Значение |
|---:|---:|---|
| Play | 0x08 | запуск выбранной песни |
| Start | 0x0C | start графа |
| Stop | 0x10 | остановка графа |
| родная Pause игры | 0x14 | переводит игровой автомат в состояние 2 |
| SetVolume | 0x1C | громкость, вызывается игрой каждый кадр |

Слоты IMediaControl:

| Слот | Смещение |
|---:|---:|
| Run | 0x1C |
| Pause | 0x20 |
| GetState | 0x28 |

## button_fe_player_next

Клик:

1. Проверить, что музыкальный объект существует и читаем.
2. Вызвать музыкальный слот Stop, 0x10.
3. Состояние плеера становится 0.
4. На следующем кадре внутриигровой цикл видит неактивный объект и сам выбирает следующую песню.

DLL не выбирает трек и не трогает RNG. Поэтому кнопка не создаёт рассинхрон.

Условия: ENABLE_MUSIC_PLAYER=1 и состояние объекта музыки читаемо. Нет дополнительной проверки gameState перед Stop.

## button_fe_player_pause

Это не родной Pause музыкального объекта. Родной слот 0x14 переводит игру в состояние 2, после чего цикл решает, что трек не активен, и может запустить новый. Поэтому DLL ставит на паузу сам DirectShow-граф, оставляя игровой автомат в состоянии 1.

Алгоритм клика:

1. Требуется gameState == 1.
2. Требуется валидный IMediaControl.
3. GetState с таймаутом 100 мс.
4. Если DirectShow state == 2, то Pause.
5. Если DirectShow state == 1, то Run.
6. Иначе клик игнорируется.

Соответствие состояний:

| OAFilterState | Значение |
|---|---:|
| Stopped | 0 |
| Paused | 1 |
| Running | 2 |

## fe_player_volume_slider

Ползунок ищется слотом окна 0x4C, а не кнопочным 0x34.

Хранение громкости:

    options singleton = *(base + 0xE5B5E0)
    musicVolume = options + 0x88
    диапазон float 0.0 .. 100.0

Соседние громкости: master +0x80, effects +0x84.

Каждый кадр FUN_009DF2B0, RVA 0x5DF2B0, считает эффективную громкость как:

    musicVolume * 0.01 * masterVolume * 0.01

и передаёт её в музыкальный объект.

### Синхронизация ползунка

Направление topbar -> настройки:

1. Пользователь двигает ползунок.
2. Слушатель читает GetValue, слот 0x10 на slider+0x54.
3. Значение ограничивается диапазоном 0..100.
4. Значение пишется в options+0x88.
5. Ставится флаг pushToMenu, чтобы окно настроек позже обновило свой slider.

Направление настройки -> topbar:

1. Покадровый хук перед FUN_009DF2B0 сравнивает текущее значение options+0x88 с кэшем.
2. Если значение изменилось не программой topbar, вызывается SetValue, слот 0x1C.
3. SetValue вызывает внутреннюю обёртку, подавляющую эхо собственного события.

Окно настроек CSettingsScreen хранит свои ползунки:

| Ползунок | Смещение |
|---|---:|
| master | +0x328 |
| effects | +0x32C |
| music | +0x330 |

Хук FUN_0075BB50, RVA 0x35BB50, перед оригиналом переносит pushToMenu в slider окна настроек. После оригинала DLL зеркалирует обратно изменения из окна. Дополнительно зеркалирование выполняется после применения настроек по call RVA 0x35C67E к FUN_0075D4B0, RVA 0x35D4B0.

Ползунок уничтожается в деструкторе topbar, vftable slot 1, RVA 0x30D0C0. При исключении во время зеркалирования указатель также сбрасывается.

## MUSIC_FAIR_RANDOM

Ключ не UI, но относится к поведению плеера.

Ванильный выбор песни внутри FUN_00455290 использует непроинициализированные данные стека. Патч RVA 0x5534D заменяет multiplication-место на честный вызов. Выбор остаётся локальным: это звуковой слой и не участвует в детерминированном состоянии мультиплеера.
