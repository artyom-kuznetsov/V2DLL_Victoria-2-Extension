### 2. F1: re-evaluate the Reforms rows when the offer changes (Ghidra, then DLL)

P46: the native row builder `FUN_006DA930` (RVA `0x2DA930`) runs once per
view. `tgcx_ReformRowImpl` only sets the enable byte while it runs, so
nothing clears a row afterwards.

1. **Read-only Ghidra research.** One writer on the project (SUBAGENTS
   §2.1). Find the caller chain of `FUN_006DA930`, and what makes the
   Politics view or its Reforms tab rebuild the rows: a dirty flag, a tab
   switch, or a refresh slot in the `CPoliticsView` vtable (RVA
   `0xA0E458`). Record findings in `docs/symbols.md` with `conf` and
   evidence (V6).
2. **Preferred fix:** when `tgcx_ReformRefresh` changes the offer, request
   the native rebuild through that path. The native code then recomputes
   every row, including clearing them.
3. **Fallback**, if no safe rebuild exists: store each row's button element
   in the row hook. On a change, toggle its enabled state through the
   button's own vtable.
4. Every new address gets a guarded signature (`check_exe.py`, V1). If a
   guard fails, rows keep today's behaviour and the log says so (R6).
5. Log the number of rows lit per pass, not only the first.
6. Add a test: "offer changed, so rows re-evaluated". Cover all three
   transitions: bill starts (only the target stays lit), bill ends
   (offered rows return), and cooldown starts (none lit).

### 3. F2: hide `tgcx_` decisions from the top-bar alert (Ghidra, then DLL)

2. Hook it with the same `tgcx_HiddenDecisionName` filter, under the same

3. Check whether the alert icon counts the list or tests each decision. If

4. Script cannot hide them (P39). Do not try.

### 4. F4 / D14: offer only what the game allows (script + DLL + mockup)

**Rule (user, 2026-10-18):** a Reforms row is lit for negotiation only if
both of these hold:

- **B:** that bill's decision passes its own `allow`, which comes from
  TGC's conditions;
- **A:** for a backward step, the native game itself would allow a
  backward reform.

How to build it:

1. **Script.** Extend `tgcx_collect_favours` (generated by
   `tools/gen_law_catalog.py`). Each catalogue bill gets one country
   variable or flag, set when that bill decision's `allow` conditions
   hold:
   - Reuse the generated `allow` block itself. Do not hand-write a parallel
     condition list (the `docs/tgc-howto.md` rule).
   - Check the P16/P21 constraints: no `if`; branch in the effect.
   - Every name gets the `tgcx_` prefix (R4).
2. **Direction rule (A).** Find TGC's own condition for a backward reform.
   Look in TGC v2.5.2's issue definitions and the `tgc_scan.py` inventory,
   not from memory. Fold it into the same flag, or into a second flag.
   Record where the condition comes from.
3. **DLL.** In `tgcx_ReformOffers`, light a row only when that bill's flag
   is set. Read the flag through `CCountry+0x1DC` `CVariables`, as the Bill
   model already does. Add tests for: flag off (not offered), flag on
   (offered), a backward step without the native permission (not offered),
   and a missing flag after a fresh load (not offered until the first
   collection, then offered).
4. **Natively allowed reforms stay native,** as now.
5. **Mockup (R10), same session.** Update board 1 of the artifact
   <https://claude.ai/artifact/Wt2YTaaM6xV8JXsUwapRV4> so it shows the
   reduced offer. Republish, refresh the boards in `E:\v2re\mockups`, then
   run `python tools/mockups/export.py`. Note the change in the report.
6. **Docs.** `docs/law-design.md` gets a section on the D14 rule.
