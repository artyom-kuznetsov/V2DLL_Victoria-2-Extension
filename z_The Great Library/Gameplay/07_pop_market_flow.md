# 07. FUN_00485E40: полный дневной поток POP

Адреса VA. Основной декомпил - decomp/v2game/FUN_00485e40_00485e40.c. Сырые зависимости также выгружены.

## Сигнатура и вход

    FUN_00485E40(market, country, playerFlag, finalPass)

Из FUN_00484060 функция вызывается так:

    FUN_00485E40(param_1, country, playerFlag, pass > 9)

Финальный проход начинается при pass > 9. Подготовительные проходы не делают реальных покупок.

## Общий граф

    FUN_00485E40
      3 x FUN_00484F90  цена/спрос наборов life/everyday/luxury
      расчётmodifiers и тарифных коэффициентов
      построение списка регионов-кандидатов
      проход провинций -> POP
        FUN_00483AA0  доход/оплатаemployment
        FUN_00485D50  аварийная/государственная закупка
        3 x FUN_00485390  покупка life/everyday/luxury
        FUN_004D1CD0  изъятие из сбережений state
        FUN_0095A5F0  вычитание товаров из пула
      FUN_0048C520  сортировка регионов-кандидатов
      FUN_004A46E0  обработка закрытой/перепрофилируемой записи
      FUN_004A76F0  добавление миграционного итога
      3 x FUN_00485960  итоговый спрос/покупка по классам

Важно: функция объединяет три подсистемы - потребности, оплату и миграцию.

## Фаза 1. Подготовка потребностей по стратам

Для каждого POP type из country+0x0804 функция вызывает FUN_00484F90 трижды:

| Класс | Смещение результатов в POP type |
|---|---:|
| life | +0x110 |
| everyday | +0x168 |
| luxury | +0x1C0 |

Перед вызовом проверяется ненулевое значение базового спроса в таблице country/type по смещениям +0x00, +0x08, +0x10 записей 0x78 байт. Если класс активен, FUN_00484F90 готовит таблицу товарных цен и объёмов.

POP type помечается в +0x3DA, если хотя бы один класс активен. Этот флаг затем влияет на миграционный выбор региона.

## Фаза 2. Коэффициенты стоимости иmodifiers

Функция многократно читает:

| Объект | Смещения |
|---|---|
| country+0x0A60 | +0x130, +0x138, +0x140, +0x148, +0x150, +0x158, +0x160, +0x168, +0x170 |
| DAT_012586DC+0x50 | +0x48, +0x4C, +0x110, +0x114, +0x170, +0x174 |
| country+0x0500 | дополнительный fixed15 множитель |

Результаты - локальные массивы шести фиксированных коэффициентов. Они используются как целевые стоимости наборов по стратам.

Смещения страны +0x0130..+0x0170 внутри блока +0x0A60 соответствуют административным/бюджетнымmodifiers, но точные имена define ещё не сопоставлены. Поэтому документируем их как массивmodifiers, не присваивая окончательные названия.

## Фаза 3. Кандидаты регионов

Перед основным проходом функция собирает массив кандидатов из регионов страны country+0x0E44. Регион пропускается, если:

    state+0x244 == 4
    state+0x248 == 0

Для каждого кандидата считается score:

1. За каждую провинцию добавляется 1000 или 200 в зависимости от совпадения с country+0x0BE4.
2. Если провинция содержит запись владельца страны в province+0x148, добавляется ещё 200.
3. Добавляется state+0x068 * 25.
4. При наличии state+0x0084 добавляется 50.
5. В кандидата сохраняются state, score, состояние и первая провинция.

Позже FUN_0048C520 сортирует этот массив. Лучший регион используется для миграции/смены типа.

## Фаза 4. Проход провинций и POP

Функция идёт по:

    country+0x09D8..0x09DC  провинции
    province+0x0194         векторы POP type
    pop+0x027C              следующий POP

POP обрабатывается, если:

    pop+0x068 -> POP type
    type+0x39C != 0
    pop+0x1D4 != 0
    pop+0x1D4+0xB0 != 0

Для активного POP создаётся временный CGoodsPool DAT_013F24B0, копируется корзина товаров и вызывается FUN_00483AA0. Она рассчитывает/выплачивает employment-часть, учитывает текущие деньги pop+0x180 и при нехватке использует сбережения через FUN_004D1CD0.

Подтверждённые поля POP:

| Смещение | Поле |
|---:|---|
| +0x058 | размер POP |
| +0x068 | POP type |
| +0x100 | страна |
| +0x110 | результаты life-спроса |
| +0x168 | результаты everyday-спроса |
| +0x1C0 | результаты luxury-спроса |
| +0x130 | цена/стоимость life |
| +0x138 | цена/стоимость everyday |
| +0x140 | цена/стоимость luxury |
| +0x180 | наличные POP, int64 |
| +0x184 | старшая часть наличных |
| +0x1D4 | employment/definition-запись |
| +0x250 | сбережения, int64 |
| +0x254 | старшая часть сбережений |
| +0x260 | служебный флаг/доля последнего прохода |
| +0x27C | следующий POP |

## Фаза 5. Покупка потребностей

Для каждого POP вызываются FUN_00485390 с параметром класса:

| Вызов | Класс | Результат в POP |
|---|---|---:|
| FUN_00485390(...,0) | life | +0x130 |
| FUN_00485390(...,1) | everyday | +0x138 |
| FUN_00485390(...,2) | luxury | +0x140 |

Если класс неактивен, в результат пишется нулевая стоимость. Если активен, функция покупает товары из рабочих пулов.

На финальном проходе, если life-потребность больше наличных и есть state savings, FUN_004D1CD0 берёт недостающую сумму из сбережений региона. Она ограничивает изъятие и локальным запасом POP+0x250/+0x25C, и государственным запасом по country+0x0E88+0x10.

## Фаза 6. Миграция/переход типа

После прохода всех провинций вызывается FUN_0048C520 для сортировки кандидатов. Лучший регион обрабатывается так:

1. Если savings state+0x228 и счётчики state+0x21C пусты, регион помечается состоянием 4.
2. Обнуляются поля +0x238..+0x240.
3. Вызывается FUN_004A46E0.
4. Накопленный объём миграции делится на define DAT_00F0ADE0 и передаётся FUN_004A76F0.
5. Итог добавляется в state+0x0230.

FUN_004A46E0 - конечный автомат проектов/переходов состояния. Значения +0x7C:

| Значение | Смысл |
|---:|---|
| 0 | проверка фабричного проекта |
| 1 | постройка провинциального здания |
| 2 | операция над фабрикой региона |
| 3 | операция над другой сущностью/проектом |
| 4 | завершение/очистка |

Точную игровую номенклатуру состояний ещё нужно уточнить, но вызов и ветвление подтверждены декомпилом.

## Фаза 7. Итоговый спрос

Если playerFlag == 0, для каждого POP type выполняются три вызова FUN_00485960:

    FUN_00485960(type+0x110, class=0, ...)
    FUN_00485960(type+0x168, class=1, ...)
    FUN_00485960(type+0x1C0, class=2, ...)

FUN_00485960 умножает остаток спроса на цену, при нехватке денег масштабирует покупку, регистрирует спрос и уменьшает рабочий пул.

Если playerFlag != 0, создается временный CGoodsPool, спрос типов объединяется FUN_0048B6F0, после чего добавляется в запись страны market+0x0824 + countryIndex*0x58. Это агрегированная учётная запись для игрока/отчётности, а не отдельная повторная покупка.

## MP-квантование

DLL патчит возврат FUN_00485E40 (RVA 0x085E40). После прохода поля POP квантуются до POP_QUANTIZE_KEEP_BITS из 15 дробных бит. По умолчанию 12 бит, шаг 8 единиц 2^-15.

Квантуемые поля:

    0x118, 0x120, 0x128, 0x130, 0x138, 0x140,
    0x180, 0x1B0, 0x1C8,
    0x1D8, 0x1E0, 0x1E8, 0x1F0, 0x1F8, 0x200, 0x208, 0x210, 0x218,
    0x250

Цель - одинаковые младшие биты на хосте и клиентах. Все игроки должны иметь одинаковые PATCH_POP_QUANTIZE и POP_QUANTIZE_KEEP_BITS.

## Статус

Подтверждено декомпилом: порядок фаз, классы потребностей, три результата в POP type, миграционный список, переход к FUN_004A46E0 и финальная агрегация. Требуют доработки: точные именаmodifiers +0x0A60+0x130..0x170, семантика всех состояний FUN_004A46E0 и полная формула FUN_00483AA0.
