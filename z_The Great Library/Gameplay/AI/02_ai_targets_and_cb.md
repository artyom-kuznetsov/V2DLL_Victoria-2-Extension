# 02. ИИ: цели войны и дипломатии

Адреса VA. Сырые декомпилы - в decomp/v2game.

## Общий target scan

FUN_0084B0F0 - AI target scan.

Вход: ECX = AI object.

Функция начинается с FUN_00851AD0, которая обрабатывает очередь устаревших целей country+0x01DC. Для каждой старой записи она ищет актуальную цель в хэше country+0x068 и при совпадении вызывает виртуальный метод country+0x13C+0x1A8.

Затем идёт основной проход по странам:

    self = countryManager[data + aiCountryIndex*4]
    for otherIndex = 1..count-1

Target scan пропускает:

| Условие |
|---|
| индекс совпадает с self |
| relation(self -> other)+0x34 != 0 |
| other или self - REB |
| существующая цель уже в списке +0x4A4 |

Если цель проходит базовый фильтр, вызывается FUN_004D61D0 и создается запись цели.

Дополнительная ветка ищет слабую цель в одной сфере:

    у цели включён флаг в self+0x0D08
    обе столицы в одном мире/сфере
    military score self+0x1A0/+0x1A4 больше или равен target
    relation+0x3C < -50
    цель ещё не является текущей сферной целью self+0x0CFC

## Обновление владельцев армий

FUN_0084ACA0 проходит country+0x07B4 и переassignет армии между целями. Для каждой военной цели:

1. Виртуальный метод +0x38 - цель войны.
2. Если owner list +0x1B0 непуст, цель передаётся подходящей армии из ai+0x214.
3. Для другой категории +0x3C используется owner list +0x1AC и метод +0x1B8.
4. FUN_0082C4D0 выполняет служебное обновление.

## FUN_008500A0 - оценка военной цели

Функция обрабатывает только активные записи country+0x07B4. Крупный блок делает:

1. FUN_0057AAB0 - очистка временных армейских контейнеров.
2. Считает силы self и target через FUN_005946A0.
3. Учитывает союзников и войны.
4. Собирает приграничные провинции из state+0x0CC и военные юниты province+0x0EC.
5. Разделяет юниты на allied и enemy списки.
6. Считает соотношение сил и формирует score.
7. Для подходящей цели создаёт команду/цель.

В декомпиле есть константы:

| Константа | Роль |
|---:|---|
| DAT_00F1783C | минимальная загрузка/готовность |
| DAT_00F177E0 | порог attack score |
| 18.0 | нормировка преимущества |
| 4.5 | нормировка劣势/удаления |
| 0.7 | штраф при участии REB |

Точные имена define ещё не сопоставлены.

## FUN_00851BD0 - дипломатический планировщик

Файл: FUN_00851bd0_00851bd0.c. Функция большая и работает по country+0x07B4, странам, отношениям и дальним целям. Она выбирает дипломатические объекты и создаёт команды через FUN_0082DC50/FUN_00828F90.

## FUN_0084DFC0 - вспомогательный target planner

Файл: FUN_0084dfc0_0084dfc0.c. Работает по AI-целям, провинциям, зданиям и заводам; вызывает FUN_008601B0 для промышленного анализа и FUN_0082C4D0 для обновления.

## FUN_0084D1D0 - colonize/expand planner

Функция вызывается из FUN_0084B0F0 при Random()%3 == 0.

Ограничение входа:

    country rank +0x1404 <= define DAT_012586DC+0x40+0x50 / 1000

Основные ветки:

1. Колонизация:
   - обход world+0x2A88..0x2A8C;
   - FUN_004CD4C0 проверяет возможность;
   - FUN_0058A0B0 создаёт colonize-команду.
2. Провинциальная инфраструктура:
   - если в регионе есть состояние/флаг, FUN_00584E90 создаёт команду.
3. Naval base:
   - проверяется лимит country+0x15C0..0x15C4;
   - FUN_005853E0 создаёт команду.
4. Заводы:
   - при нехватке лимита FUN_0084C470 пытается создать новый завод.
5. Армия/юниты:
   - planner считает провинции, стены, расстояния, recruiting buildings;
   - выбирает лучшую провинцию;
   - FUN_00589840 создаёт команду найма/постройки.

Функция активно использует Random() через FUN_009B7610.

## Casus belli scan

FUN_0092EDE0 - общий can-use/CB scan, вызываемый как target scan, так и дипломатией.

Структура:

| Смещение | Поле |
|---:|---|
| +0x08 | начало CB list |
| +0x0C | конец CB list |
| +0x10 | общее хранилище CB |
| +0x18.. | связи |

Алгоритм:

1. Берёт исходный шанс/вес +0x08.
2. Для каждого CB читает список триггеров +0x08..+0x0C.
3. Каждый триггер проверяется virtual +0x18.
4. Успешный CB уменьшает шанс: current = current * weight / 1000.
5. Если вес обнулил шанс, перебор прекращается.
6. Итог возвращается как fixed-point вес.

Позиции +0x20 и +0x1C - weight and base value.

## Модовые хуки

### Relation prefetch

AI target scan читает relation+0x34 для всех стран. Vtable slot:

    RVA 0xA2773C -> FUN_0084B0F0

Мод PATCH_PREFETCH_AI_RELATIONS заменяет vtable slot на prefetch-функцию, которая до скана загружает relation rows в кэш.

### CB cull

SCAN-функция RVA 0x52EDE0 / VA 0x0092EDE0 вызывается на:

    VA 0x0085DCDA - war scan
    VA 0x0085E5FB - diplomacy scan

PATCH_CULL_CB_CHECKS подменяет обе точки. Кэш строится на день:

1. Для каждого attacker заранее вычисляются attacker-only триггеры.
2. Невозможные CB помечаются dead.
3. CB с флагом always при успехе сразу дают ответ 1.
4. Если у defender уже есть CB, проверяется только не-always тип из relation+0x50.
5. Остальные невозможные CB не проверяются.

Менеджер CB:

    DAT_0131ACAC = RVA 0xF1ACAC
    count/list = manager+0x0C..0x10
