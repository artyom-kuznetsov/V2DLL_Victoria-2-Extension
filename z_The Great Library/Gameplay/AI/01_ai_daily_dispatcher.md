# 01. Ежедневный диспетчер ИИ

## Покадровая очередь

FUN_006874C0 - scheduler одного кадра.

Алгоритм:

1. Получает queueRef; очередь - linked list:
   - queue+0x00 - голова;
   - queue+0x08 - конец/хвост;
   - queue+0x0C - счётчик.
2. Извлекает первый узел.
3. Если node+0x10 != 0, узел уже активен; иначе помечается 1.
4. Берёт countryIndex из node+0x04.
5. Если country существует, имеет провинции и country+0x0208 != 0, вызывает FUN_0081E9E0.
6. Выходит не позднее 20 мс: если QPC - start > 0.02, прекращает обработку в этом кадре.

Мод PATCH_FAST_AI_QUEUE оборачивает FUN_006874C0 на call site RVA 0x2557C4 / VA 0x006557C4. На максимальной скорости 4 он повторяет FUN_006874C0, пока очередь не пуста или не истекут 250 мс.

## FUN_0081E9E0 - daily AI dispatcher

Условия:

    tag != REB
    country+0x09D8 < country+0x09DC

Порядок:

| Шаг | Функция | Назначение |
|---:|---|---|
| 1 | FUN_00821510 | приоритеты |
| 2 | FUN_005DCAC0 | армии/юниты |
| 3 | virtual plan | FUN_004A5170 |
| 4 | FUN_005DCB70 | восстановление контекста |
| 5 | FUN_00820DF0 | дипломатия |
| 6 | FUN_0081F3B0 | фабрики и субсидии |
| 7 | FUN_0081FB00 | постройка фабрик |
| 8 | FUN_00820760 | провинциальные здания |
| 9 | FUN_0081E5B0 | реформы |
| 10 | FUN_0081E280 | армия |
| 11 | FUN_00821190 | решения |

## FUN_00821510 - приоритеты

Проходит список country+0x07B4. Для каждой записи:

    если entry+0x0EC < 1, priority entry+0x0A0 = 0
    иначе priority = *(entry+0x0E8)

Это обновление внутреннего score перед выбором целей.

## FUN_005DCAC0 - подготовка армии

Для армейского списка:

| Смещение | Поле |
|---:|---|
| +0x38 | список юнитов |
| +0x8C | суммарная мощь |
| +0x90 | голова временного списка |
| +0x94 | текущий узел |
| +0x98 | счётчик |

Функция очищает +0x8C, создаёт узлы по 0x10 байт и для каждого юнита:

    unit+0x78 = армия
    army+0x8C += unit+0x3C

## FUN_00820DF0 - дипломатические действия

Функция идёт по country+0x0CE4 и для кандидатов:

1. FUN_00911760 проверяет базовую допустимость.
2. Виртуальный метод объекта +0x6C проверяет доступность.
3. Требуется состояние объекта+0x24 == 1.
4. По типу объекта вызывается специализированный scorer:

| Тип | Функция |
|---:|---|
| 0x081E | FUN_0083DE70 |
| 0x0332 | FUN_00841640 |
| 0x038D | FUN_008419C0 |
| 0x0470 | FUN_00842A00 |
| 0x0897/0x0898 | 100, если нет войны, иначе 0 |
| 0x08C6..0x08CB | серия дипломатических оценок |
| 0x08D5/0x08D6 | FUN_00844050/FUN_00844140 |
| 0x09FA | FUN_00843A10 |
| 0x09FB | FUN_00843B90 |
| 0x0A02 | FUN_00843170 |

5. Score < 50 - отклонить, объект state = 2.
6. Score >= 50 - Random()%100 против score; успех переводит объект в state = 3 и создаёт команду.

Для разных стран базовый шанс обычно 100; для самой страны многие ветки получают 0 или 100 в зависимости от типа.

## FUN_0081E280 - армия

Функция активна для цивилизованных стран при country+0x067C == 0.

Она считает:

1. Сумму province+0x0050 по всем провинциям.
2. Число армий, у которых виртуальный метод +0x38 вернул истину.
3. Для каждой армии - число юнитов, у которых unit+0x30 != 0 и type+0x42 != 0.

Далее сравнивает отношение целевой численности к текущей с порогом DAT_013173CC. Если армий не хватает, выбирает подходящие армии и создаёт команду FUN_005E1000.

В декомпиле есть явные сравнения строк:

    irregular
    cavalry

Они используются при отборе юнитов.

## FUN_0081E5B0 - реформы

Условие: country+0x067C == 0.

Есть два режима:

1. Если отношение доходных статей country+0x0160 к country+0x0168 ниже порога DAT_013173CC:
   - собирает подходящие реформы;
   - для каждой провинции считает state+0x244 / 2;
   - выбирает максимум;
   - создаёт команду FUN_005E1000.
2. Иначе:
   - сразу сравнивает state+0x244 с делением на 3;
   - при улучшении создаёт команду FUN_005E1000.

## FUN_00821190 - решения

Создаёт CEventScope через FUN_008A8650 и копирует тег/индекс AI-объекта +0x30/+0x34. Затем лениво создаёт менеджер решений DAT_01319730.

Менеджер решений:

| Смещение | Поле |
|---:|---|
| +0x0C..+0x10 | список A |
| +0x28..+0x2C | список B |

Для каждой записи решения:

1. Вызывается trigger slot +0x18: potential.
2. Повторно slot +0x18: allow-проверка.
3. slot+0x24 +0x18 - AI-вес.
4. slot+0x40 +0x18 - allow.
5. Вес умножается на 100.
6. Random()%100 сравнивается с весом.
7. При успехе создаётся объект опции/команды через FUN_008A88D0 и FUN_00905B30.

Список A обрабатывается первым, затем список B.
