# 04. ИИ и события: MTTH и авто-выбор опций

Адреса VA. Сырые декомпилы - в decomp/v2game.

## Планировщик событий

FUN_008A7CD0 вызывается из дневного тика мира.

Сначала создаётся CEventScope через FUN_008A8650 со случайным scope id FUN_009B7950(0x20,0).

День определяет тип прохода:

    day = (world_time - 43800000) / 24
    day % 2 == 1 -> country events
    day % 2 == 0 -> province events

### Country pass

Обходится менеджер стран, индексы с 1. Для каждой страны:

1. Требуется ненулевой country+0x020 и провинции.
2. Обходится список событий country+0x08..0x0C.
3. Virtual trigger slot event+0x30+0x18 проверяет условие.
4. FUN_008AE380 вычисляет шанс.
5. Инкрементируется глобальный счётчик DAT_00F20C14.
6. Берётся значение MT из предвычисленного пула FUN_006859C0:
   - сдвиги/умножения MT state;
   - result % 1000000;
7. Если result < chance и событие не дублируется в кэше, вызывается FUN_008A8120.

### Province pass

Обходится провинция из world+0x0ACC, только с владельцем province+0x12C != 0. События лежат в province+0x14..0x18. Шанс вычисляется с mode 2. Остальное одинаково.

## FUN_008AE380 - расчёт MTTH

Вход:

| Параметр | Значение |
|---|---|
| event+0xC0 | блок modifiers |
| scope | CEventScope |
| mode | 1 country, 2 province |

Базовое MTTH хранится в event+0x08.

Алгоритм:

1. Для каждого модификатора в списке +0x0C..0x10:
   - virtual +0x18 проверяет применимость;
   - коэффициент +0x20 - thousandths;
   - base = base * coefficient / 1000.
2. Итог клампится.
3. Итоговый шанс:

       chance = modeLimit * 1000000 / (mtth / 1000)

4. Возвращается 1..1000000.

Если base <= 0, шанс становится 1000000.

## FUN_008A8120 - срабатывание события и выбор опции

Вход: ECX = event, stack аргумент - scope record.

Определяется владелец scope:

| Условие | Владелец |
|---|---|
| scope+0x0C != 0 | province по индексу +0x10 |
| province+0x12C == 0 и есть state | владелец state |
| иначе | страна |

Далее две большие ветки.

### AI-владелец

Условие:

    ownerIndex < session+0x0AF0 - session+0x0AEC >> 2
    session+0x0AEC[ownerIndex] == 0
    country+0x0208 != 0

Это признак AI.

Алгоритм выбора опции:

1. Для каждой опции event+0x0B0..0x0B4 вызывается FUN_008AEB00.
2. Суммируются веса.
3. FUN_00401000/FUN_00B31C00 даёт случайное float.
4. Если random float < total/1000/100, используется direct random-выбор опции.
5. Иначе идёт нормированное распределение:

       bucket = optionWeight / 1000 / scale
       cumulative >= Random()%100 -> выбрать эту опцию

6. FUN_008A88D0 создаёт объект опции.
7. FUN_00907D40 применяет выбранную опцию.
8. Команда отправляется через world+0x0B24+0x38+0x18.

### Human-владелец

Если владелец - локальный игрок:

1. Проверяется active country через world+0x0B24+0x58.
2. FUN_0068B610 получает UI state.
3. Если событие может показываться, создаётся popup/object через FUN_008A8F30.
4. FUN_006480E0 добавляет его в очередь.

Если владелец - человек, но не локальная машина, popup не создаётся. Это важно для MP.

## FUN_008AEB00 - вес опции

Функция вычисляет вес опции события.

Вход:

| Смещение | Поле |
|---:|---|
| +0x08 | базовый вес |
| +0x0C..0x10 | список factors |
| +0x1C | итоговый множитель |

Для каждого фактора:

1. Список триггеров factor+0x08..0x0C проверяется virtual +0x18.
2. Если триггеры прошли, weight = weight * factor+0x20 / 1000.
3. Первый неудачный триггер прекращает factor.
4. Итог умножается на event+0x1C / 1000.

Если вес падает ниже 1, обработка прекращается.

## Random и MP

Событийный проход - один из крупнейших источников расхождений:

1. Country/province trigger может вернуть разный результат.
2. MTTH chance тогда отличается.
3. Число draws отличается.
4. AI option choice вызывает ядро MT FUN_009B7610 напрямую, минуя обычные wrappers.

Модовые диагностики:

| Хук | Назначение |
|---|---|
| FUN_008A7CD0 entry | daily event scan |
| VA 0x008A7EB1 | country event compare |
| VA 0x008A8092 | province event compare |
| FUN_008A8120 fire | лог события и scope |
| FUN_009B7610 | прямой MT core |
