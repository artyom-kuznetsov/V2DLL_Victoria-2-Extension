# 03. POP: потребности, покупки и бюджетные выплаты

Адреса VA. Сырые декомпилы - в decomp/v2game.

## Место в дневном рынке

В FUN_00484060 общий порядок покупок такой:

    FUN_00482FF0  проекты/строительство
    FUN_00487410  государство
    FUN_00485E40  POP и фабрики

POP-пакет вызывается внутри FUN_00485E40. Модификаторы нужд страны применяются в двух местах: симуляция использует их при покупке, а карточка POP в ванили показывает базовые количества. DLL-патчи POP_* исправляют только отображение, кроме бюджетных выплат.

## Подготовка спроса FUN_00484F90

Файл: FUN_00484F90_00484F90.c.

Функция агрегирует количество товаров в наборах нужд и пересчитывает столбцы demand/price для нужд. Она работает с вектором товаров param4+0x48..+0x4C и заполняет таблицу по индексу товара:

| Смещение таблицы | Назначение |
|---:|---|
| +0x18 | объём/вес, fixed15 |
| +0x30 | возможный доступный объём |
| +0x60 | другая агрегированная цена/вес |

Статус: подтверждаются суммирование и пересчёт таблицы. Названия полей ещё условные.

## Покупка нужд FUN_00485390

Файл: FUN_00485390_00485390.c.

Это ядро покупки набора нужд POP. Категория param3:

| Категория | Значение |
|---|---:|
| life | 0 |
| everyday | 1 |
| luxury | 2 |

Ключевые поля POP:

| Смещение | Поле |
|---:|---|
| +0x68 | POP type |
| +0x180 | доступная сумма, int64 |
| +0x184 | служебная денежная величина/резерв |
| +0x1D0 + category | флаг неудовлетворённой категории |
| +0x250 | государственный/страховой запас, int64 |
| +0x260 | накопленный дефицит категории |
| +0x26C | счётчик дней без life-нужд |

Общий алгоритм:

1. Умножает стоимость набора на масштаб POP и модификаторы.
2. Для luxury дополнительно делит на порог и учитывает требования страны.
3. Если денег POP не хватает, берёт недостающую часть из запаса +0x250 через FUN_004D1CD0.
4. Покупает товары из рыночных пулов через FUN_0095A5F0.
5. Отмечает неудовлетворённость категории в +0x1D0.
6. Обновляет счётчик жизни +0x26C.
7. Возвращает цену/стоимость фактического набора в выходной int64.

Если запрошенная стоимость равна нулю, категория сразу помечается неудовлетворённой. Если не хватает товаров, покупается доступная часть, а дефицит накапливается.

## Вспомогательная покупка FUN_00485D50

Файл: FUN_00485D50_00485D50.c.

Функция берёт amount с POP +0x180, умножает на цену, вычитает из пула FUN_0095A5F0 и возвращает сумму покупки. При доступности +0x250 добавляет часть из государственного запаса через FUN_004D1CD0.

Используется как вспомогательный путь оплаты; точную семантику вызывающего контекста нужно уточнять по FUN_00485E40.

## Модификаторы нужд

Реестр описаний создаёт FUN_00449120. Ванильный порядок описаний:

    poor_life, rich_life, middle_life
    poor_everyday, rich_everyday, middle_everyday
    poor_luxury, middle_luxury, rich_luxury

Парсер пишет значение по позиции описания, а движок читает блок страны +0xA60 по слотам:

| Слот | Категория/страта |
|---:|---|
| 0x26..0x28 | life poor/middle/rich |
| 0x29..0x2B | everyday poor/middle/rich |
| 0x2C..0x2E | luxury poor/middle/rich |

Для life и everyday ваниль перепутала middle и rich. POP_FIX_NEEDS_MODIFIERS меняет местами непосредственные операторы name/id/slot в реестре, делая порядок poor/middle/rich одинаковым.

Значение хранится в тысячных; множитель:

    32768 + value * 32768 / 1000

Отрицательный множитель ограничивается нулём.

## Бюджетные выплаты FUN_0050B9B0

Файл: FUN_0050B9B0_0050B9B0.c.

Функция раздаёт расходы бюджета типам POP. Сигнатура stdcall, ret 0x10: страна, число типов, список типов, флаг.

Фаза 1 считает для каждого POP type сумму:

    population_share * weight

Веса типа POP:

| Смещение | Вес |
|---:|---|
| +0x320 | life_needs_income, int64 fixed15 |
| +0x328 | everyday_needs_income |
| +0x330 | luxury_needs_income |

Соответствие статей бюджетных выплат:

| Статья | Категория |
|---|---:|
| education | 0 |
| administration | 1 |
| military | 3 |
| reforms | не совпадает напрямую |

POP_BUDGET_PAYOUT_NEEDS_SCALED временно умножает веса всех типов на модификаторы нужд страны по страте, выполняет фазу 1, затем восстанавливает оригинальные веса. Выплата типу падает пропорционально его неудовлетворённости; свободные деньги остаются в казне.

## Отображение POP

FUN_00983CB0 - карточка POP со списками life/everyday/luxury_needs_list. В ванили она не применяет модификаторы страны. POP_CARD_NEEDS_AFFECTED_BY_NEEDS_MODIFIERS_FIX умножает базу карточки на те же коэффициенты страты. Это чистый UI-слой и не влияет на симуляцию.
